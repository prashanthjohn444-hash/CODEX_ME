
Application Programming Interface(API)

API

API stands for Application Programming Interface. The APIs in this section are web APIs.

A web API is the contract between a service and the programs that use it: which URLs exist, which HTTP methods they accept, and what the response looks like (usually JSON, sometimes XML). That contract is also a service-level agreement (SLA) for the provider.

In web development, an API is a set of HTTP request messages plus a definition of the response body.

Web APIs have moved away from SOAP and service-oriented architecture (SOA) toward REST-style resources.

Social platforms use APIs so one post can appear in many places. Twitter's REST API (now the X API) is one example: core data on one set of endpoints, search and trends on another.

This section is about a RESTful API: HTTP methods GET, PUT, POST, and DELETE.

Building API

A RESTful API uses HTTP to GET, PUT, POST, and DELETE data. Days 26 and 27 gave you Flask and MongoDB. Day 29 puts them together. Any app with CRUD (Create, Read, Update, Delete) talks to a database through an API.

To build one, you need the HTTP request / response cycle.

HTTP(Hypertext Transfer Protocol)

HTTP is the protocol between a client and a server. Here the client is a browser (or Postman). The server is the machine that holds the files or data.

HTTP delivers resources on the web: HTML, images, query results, scripts, JSON, and other types.

The browser is an HTTP client. It sends a request. The web server sends a response.

HTTP request / response cycle
output.txt
HTTP Clients                  HTTP over TCP/IP                 HTTP Server
(Web Browser)                                                  (Web Server)

  desktop, laptop, phone  ---- HTTP Request Message ------->   rack of servers
  desktop, laptop, phone  <--- HTTP Response Message ------    rack of servers



The client (browser, phone, or API tool) opens a connection.

It sends an HTTP Request Message.

The server answers with an HTTP Response Message.

The transfer runs over TCP/IP.

When the cycle finishes, the server closes the connection (HTTP/1.0) or may keep it (Connection: keep-alive on HTTP/1.1).


Structure of HTTP

Client-server model: open connection → request → response → done.

Request and response share the same four-part shape:


An initial line (request line or status line).

Zero or more header lines.

A blank line (CRLF by itself).

An optional message body (file, form data, or JSON).


Initial Request Line(Status Line)

The request line is not the same as the response status line.

A request line has three parts, separated by spaces:


Method name (GET, POST, HEAD, …)

Path of the resource

HTTP version


Example:
output.txt
GET / HTTP/1.1


GET reads a resource. POST creates one.

Initial Response Line(Status Line)

The status line also has three parts, separated by spaces:


HTTP version

Status code

Reason phrase


Examples:
output.txt
HTTP/1.0 200 OK
HTTP/1.0 404 Not Found


Common codes:




  Code
  Phrase
  Meaning





  200
  OK
  Request succeeded. The body is the resource.



  201
  Created
  A POST created a resource.



  302
  Found
  Redirect (Flask redirect uses this).



  400
  Bad Request
  The client sent a bad request.



  404
  Not Found
  No resource at that path.



  500
  Server Error
  The server crashed or raised an exception.




Full lists: httpstatuses.com and httpstatusdogs.com.

Header Fields

Headers describe the request, the response, or the body.

The message body

After the blank line, a message may carry a body.


Response body — the resource (HTML, JSON, an image) or an error page.

Request body — form fields or an uploaded file.


When there is a body, these headers usually appear:




  Header
  Example
  Meaning





  Content-Type
  text/html, application/json, text/plain, text/css, image/gif
  MIME type of the body



  Content-Length
  1764
  Number of bytes in the body




Request Methods

These four methods are the ones we implement for an API / CRUD app.




  #
  Method
  CRUD
  What it does





  1
  GET
  Read
  Retrieve data from a URI. Must not change data.



  2
  POST
  Create
  Send data to the server (new post, file upload, HTML form).



  3
  PUT
  Update
  Replace the target resource with the uploaded content.



  4
  DELETE
  Delete
  Remove the resource.




A browser address bar only sends GET. Use an HTML form for POST, or a tool such as Postman / Insomnia for PUT and DELETE. Day 29 uses Postman.
